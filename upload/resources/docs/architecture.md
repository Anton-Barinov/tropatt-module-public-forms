# Архитектура интеграции публичных форм (Public Forms & Booking)

## 1. Сверка с Intake и Calendar Core
- Публичные формы **не создают дублирующих сущностей**.
- Заявка из формы маршрутизируется напрямую в сущность `intake` с источником `source_type = 'public_form'` и привязкой к указанному `project_id` / ответственному.
- Запись на встречу (Booking) резервирует слот в календаре `events` с проверкой занятости:
  - Проверка пересечения: `WHERE user_id = :uid AND start_at < :slot_end AND end_at > :slot_start`.
  - Транзакционный лок / atomic check предотвращает double booking слота.

## 2. Антиспам и защита публичной конечной точки
- **Honeypot field**: Скрытое поле `_hp_website`, если заполнено ботом — заявка тихо отклоняется или маркируется спамом.
- **Time threshold**: Поле `_t_token` с timestamp открытия формы. Если отправка произошла быстрее 3 секунд — спам.
- **IP Rate Limit**: Не более 5 заявок в минуту с одного IP.
- **No Workspace Spoofing**: ID рабочего пространства зашит в `public_form_id` и никогда не принимается от браузера клиента.
